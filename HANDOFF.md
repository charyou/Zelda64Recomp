### Implemented contract boundaries

- The game patch reserves a capture token only while armed, snapshots resolved MM/environment and bounded LightContext state immediately before `Play_Draw`, compares scalar post-draw state without rescanning, emits explicit OPA/XLU stream markers, finalizes binding evidence after draw and publishes it before graphics-task submission. - Capture-only binding attempts and finalized receipt sidecars observe the existing source-owner decisions. RT64 accepts an annotation only on exact token, stream, normalized command PC, slot and command/payload bytes. Task/list entry begins unassociated; list execution and marker spans carry unique occurrence/order identities. Missing evidence is unavailable/unassociated rather than inferred.
- RSP light snapshots carry optional semantic lineage through the same production load/copy/equal-value lifecycle, with invalidation on reload or color edit. Framebuffer source rows serialize actual semantic source records before the existing empty-vector dummy, and receiver rows are emitted at production classification/submission branches with `not_evaluated` later gates after a short circuit.
- Snapshot/burst/benchmark capture uses a bounded single-writer queue, versioned manifest/checksums, build/backend/device/session/workload/render/config identities, explicit truncation/drop status, 8192-row detailed caps, default 256 MiB outstanding budget and 120-metadata history. Benchmark mode omits detailed source/receiver/binding rows. Stage 4 selected output is explicitly `not_captured`.
- Plume gained a success-returning exact-range timestamp read alongside the legacy API. Vulkan validates availability/valid bits and converts by timestamp period; D3D12 validates support/frequency and converts to nanoseconds; Metal provides the same range/status surface. RT64 allocates a fixed 128-query pool before measurement and reads it only after the existing completion point. No new waits or submissions were added.

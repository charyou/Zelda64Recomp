## Temporal identity — **CONFIRMED** counterexample

`lib/rt64/tests/wp3_identity_fixture.cpp` constructs real `DrawData`/`GameCall` inputs and calls production `RaytracingSceneRecord::beginOccurrence`, `describe` (including `computeProvenance`), `addSurface`, and `finalize` in `rt64_raytracing_scene.cpp`. It supplies stock matched-moved transform provenance (`2`), one tagged matrix-group ID (`0x1234`), identical material inputs and relative triangle topology, but distinct model-space positions for logical A, B, and inserted X. Explicit velocity is supplied only in the velocity case. No identity algorithm is copied into the fixture. Build/run: Ninja target `rt64_wp3_identity_fixture`; output: `_working-directory/diagnostics/2026-09-25-wp3/wp3-identity-fixture.csv`.

Every row reports `Tagged` identity. Key `K0=7516152991368647085`, `K1=15177678481979189653`, `K2=5428447996248272414`. “Key owner” is the previous frame's logical surface with that reported identity. `Continuous` is the production continuity result; it does **not** establish correct logical correspondence.

| Case/current | Expected previous | Reported key / previous owner | Continuity | Motion | Correspondence |
|---|---|---|---|---|---|
| stable A | A | K0 / A | Continuous | Interpolated | Correct |
| stable B | B | K1 / B | Continuous | Interpolated | Correct |
| reorder B | B | K0 / A | Continuous | Unknown | Falsely accepted identity; motion rejected |
| reorder A | A | K1 / B | Continuous | Unknown | Falsely accepted identity; motion rejected |
| insert X | New | K0 / A | Continuous | Unknown | Falsely accepted identity; motion rejected |
| insert A | A | K1 / B | Continuous | Unknown | Falsely accepted identity; motion rejected |
| insert B | B | K2 / none | New | Unknown | Conservatively rejected |
| remove X, now A | A | K0 / X | Continuous | Unknown | Falsely accepted identity; motion rejected |
| remove X, now B | B | K1 / A | Continuous | Unknown | Falsely accepted identity; motion rejected |
| reorder with velocity B | B | K0 / A | Continuous | Interpolated | **Falsely accepted identity and trusted motion** |
| reorder with velocity A | A | K1 / B | Continuous | Interpolated | **Falsely accepted identity and trusted motion** |

Equal topology does not reject ordinal swaps. Different shape rejects motion only without explicit velocity. `finalize()` accepts the ordinal's previous topology as continuity and, with explicit velocity, accepts `Interpolated` despite the swapped logical owner. Thus false correspondence reproduces. Current ADR-016 evidence is **usable only with an additional history-validity/correspondence guard** for a bounded temporal experiment; Tagged identity and trusted motion alone are insufficient. This task does not design that guard.

## Decision input for Opus

1. **Is WP3 identity sufficiently qualified for a temporal experiment?** No, not as-is. Ordinal-based Tagged identity can report `Continuous` and `Interpolated` for the wrong logical surface. A bounded experiment may consume it only with an additional correspondence/history-validity guard.
2. **Is source-collection work demonstrated necessary before meaningful temporal evaluation of the tested local/GI path?** No. Binding-derived availability changed the collected list, but the changing record was not a selected local Direct or GI candidate in the tested continuing-scene window.
3. **Demonstrated vs future ceiling:** A stable game point can fail historical binding/publication and later enter the collected set; repeated intro runs show one-record population changes with zero selected-pixel effect in this shot. Collection still depends on successful historical binding and therefore has a real coverage ceiling. Whether that ceiling causes material candidate or temporal input churn in another local-light scene is unresolved.
